# OidcForge.EntityFramework.Storage — release notes

Release notes of the package `OidcForge.EntityFramework.Storage` (original id `IdentityServer4.EntityFramework.Storage`).
The overview of the whole release, the upgrade guide and the known limitations are in the
[release notes of the repository](../../RELEASE_NOTES.md). The baseline of the comparisons is IdentityServer4 4.1.2.

## 4.2.0 (unreleased)

### Dependencies

| Dependency | Version |
|---|---|
| `OidcForge.Storage` | 4.2.0 |
| `Mapster` | 10.0.13 (replaces `AutoMapper`) |
| `Microsoft.EntityFrameworkCore` | 10.0.12 |
| `Microsoft.EntityFrameworkCore.Relational` | 10.0.12 |

Target framework: `net10.0` only (was `netcoreapp3.1` … `net6.0`).

### Added

- **Signing keys in the database:** entity `Key`, `PersistedGrantDbContext.Keys` / `IPersistedGrantDbContext.Keys`,
  table configuration `OperationalStoreOptions.Keys` (default table name `Keys`) and `SigningKeyStore`
  (`LoadKeysAsync`, `StoreKeyAsync`, `DeleteKeyAsync`), the store of automatic signing key management.
- Table `Keys`: `Id` (`nvarchar(100)`, primary key), `Version` (`int`), `Created` (`datetime2`), `Algorithm` (`nvarchar(100)`),
  `DataProtected` (`bit`), `Data` (`nvarchar(max)`; key material, protected with data protection by default).

### Changed

- **Mappers:** entity ↔ model mapping uses Mapster with generated code (`Mappers/Generated`, regenerated by the `GenerateMappers` target)
  instead of AutoMapper with runtime reflection. The mapper classes were internal; `ToModel()` / `ToEntity()` are unchanged.
- **Grant redemption is race-safe:** `PersistedGrantStore.GetAndRemoveAsync` deletes the row and treats a concurrency conflict as "not found",
  so of two concurrent requests for the same authorization code only one gets it; the other no longer fails with an unhandled exception.
- EF Core 10; the table layout of the configuration store and of the grant tables is unchanged (the 2020 reference migrations still describe it).

### Breaking changes

- `net10.0` only.
- **`IPersistedGrantDbContext` has a new member `DbSet<Key> Keys`.** Custom implementations must add it; classes derived from
  `PersistedGrantDbContext` get it automatically.
- **A migration is required for the `Keys` table** (see below), also when key management stays disabled.

### Tests

16 unit and 45 integration tests on Windows; 16 and 90 on Linux and macOS, where the integration tests also run against SQLite
(including the `Keys` table and the concurrent redemption of a grant).

### Upgrading

1. Replace `IdentityServer4.EntityFramework.Storage` with `OidcForge.EntityFramework.Storage`.
2. Create and apply the migration for the new table:

   ```powershell
   dotnet ef migrations add Keys -c PersistedGrantDbContext -o Migrations/PersistedGrantDb
   dotnet ef migrations has-pending-model-changes -c PersistedGrantDbContext   # must report no changes afterwards
   ```

   Reference migrations and SQL scripts for SQL Server: `src/EntityFramework.Storage/migrations/SqlServer`.
3. If you had custom table names or a custom schema, check that `OperationalStoreOptions.Keys` follows your convention.
4. Rows of the grant tables need no conversion: persisted grants keep the JSON format of IdentityServer4 4.x
   (rows written by the `4.2.7` / `4.2.8-ideals` builds are the exception, see the [repository release notes](../../RELEASE_NOTES.md#upgrading)).
